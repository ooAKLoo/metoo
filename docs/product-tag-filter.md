# Product Thinking: Tag Filter (WHERE + WHAT)

## 核心洞察

用户收藏的美食内容天然存在两个维度：

| 维度 | 回答的问题 | 已有方案 | 新增方案 |
|------|-----------|---------|---------|
| **WHERE（城市）** | 这个城市有什么好吃的？ | CityGallery 底部城市卡片 | - |
| **WHAT（品类）** | 我想吃 X，去哪里？ | 无 | 标签筛选栏 |

单独用哪个维度都有价值，**组合使用才是杀手级体验**：
- 城市 + 品类 = "成都的烧烤" → 精准推荐
- 仅品类 = "所有收藏的咖啡店" → 跨城市主题浏览
- 仅城市 = 原有行为不变

## 数据来源

标签不需要用户手动打，**直接从标题自动提取**。B 站和小红书的美食内容标题天然包含品类关键词（烤鱼、蛋糕、抹茶、提拉米苏、烧烤等）。

提取方式：关键词词典匹配 → 映射到品类分类 → 聚合计数 → 按热度排序。

## 设计决策

### 为什么用品类分组而非裸关键词？

- 裸关键词会导致标签过多、过碎（"提拉米苏" 2条、"马卡龙" 1条 → 不如合并为 "甜品" 3条）
- 品类分组让标签栏更紧凑，信息密度更高
- 每个品类带 emoji 前缀，视觉辨识度高（🔥烧烤、🍲火锅、☕咖啡）

### UI 位置选择

标签栏放在 **sidebar 列表头部和内容之间**，原因：
1. 靠近它所筛选的内容（列表），操作反馈直观
2. 不占用地图空间
3. 横向滚动，不压缩列表纵向空间
4. 与城市筛选组合时，筛选指示器并排显示，一目了然

### 筛选交互

- 点击标签 = 切换选中（toggle）
- 标签栏始终可见（展示数据概览价值）
- 筛选生效时，在标签栏下方显示 chip 式筛选指示器，带 × 关闭
- 城市筛选和品类筛选**独立可组合**，各有自己的 chip

## CityGallery 遮挡修复

CityGallery（z-10）被 sidebar（z-20, w-[340px], left-3）左侧遮挡约 352px。

修复方案：gallery 的 `left` 根据 `sidebarOpen` 动态偏移 356px，带 300ms ease-out 过渡。sidebar 状态统一存入 `useMapStore`，避免 prop drilling。
